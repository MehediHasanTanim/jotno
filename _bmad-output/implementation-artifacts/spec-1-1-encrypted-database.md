## Intent

**Problem:** Jotno has no codebase, and its entire promise rests on a local encrypted database. The failure that matters is not a crash — it is a build that silently ships upstream SQLite, writes plaintext, and looks perfectly healthy until someone pulls the file off a device.

**Approach:** Create the Flutter project in `jotno/` with the mandated source tree and pinned dependencies, switch `package:sqlite3` to the SQLite3MultipleCiphers build via its pubspec hook, and make the app **throw at startup** — in release as well as debug — when the encrypted library is not the one that shipped.

## Boundaries & Constraints

**Always:**
- Fail closed. Before any query runs, `PRAGMA cipher` is executed; an **empty result set** means upstream SQLite shipped, and the app throws rather than opening the database. Use `throw`, never `assert` — asserts are stripped in release, which is precisely the build this check exists to catch.
- `PRAGMA key` is applied inside the connection `setup` callback before any other statement, with the key inlined and SQL-escaped (`'` → `''`); the pragma does not accept bind parameters.
- `PRAGMA key` does not validate. Follow it with `select count(*) from sqlite_master` so a wrong key fails immediately and loudly rather than at some later read.
- Every table carries `id TEXT` (client-generated UUIDv7), `created_at`, `updated_at`, `deleted_at`, `device_id`.
- Migrations are generated by `drift_dev make-migrations`. Hand-written migrations are not permitted.
- The Flutter project lives in `jotno/`, separate from `_bmad/` and `_bmad-output/`.

**Ask First:**
- **Flutter version — RESOLVED before approval.** The toolchain was upgraded from 3.41.9 to **3.47.2 / Dart 3.13.2**, matching the spine's pin. Build against that; do not develop on a different SDK than the one that ships.
- Any deviation from the pinned dependency set.
- Anything that would make the cipher check conditional, skippable, or debug-only.

**Never:**
- Add `sqlcipher_flutter_libs`, `sqlite3_flutter_libs` (both discontinued) or `riverpod_generator`.
- Build feature code, UI, or any entity beyond the single schema-v1 smoke table.
- Build `AppLogger`, `HeadlessScope`, `AttachmentStore`, the contributor interfaces, `Result`/`AppFailure`, or the reference fixture — all Story 1.2.
- Implement real key management. Story 1.1 supplies the key through an injectable seam with a development implementation; Story 1.13 replaces it with the double-wrapped DEK.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Encrypted build shipped | `source: sqlite3mc` resolved | `PRAGMA cipher` returns ≥1 row; key applied; database opens | N/A |
| Upstream SQLite shipped | hook misconfigured or absent | `PRAGMA cipher` returns 0 rows — silently, no exception from SQLite | Throw `UnsupportedError` before any query; app does not start |
| Wrong key against existing DB | correct library, incorrect key | `select count(*) from sqlite_master` fails | Throw a distinct, named failure — not the same error as a missing cipher |
| Key contains a single quote | key `it's-a-key` | Escaped to `it''s-a-key`; database opens normally | N/A |
| Fresh install, no DB file | empty app-support directory | Database created encrypted at schema v1 | N/A |

## Design Notes

The check must be a `throw`, not the `assert` shown in Drift's own documentation. Drift's official *example app* uses the throwing form for exactly this reason, and it is the form that satisfies fail-closed.

```dart
setup: (db) {
  if (db.select('pragma cipher').isEmpty) {
    throw UnsupportedError(
      'Jotno requires the SQLite3MultipleCiphers build. '
      'The shipped library is unencrypted — refusing to open the database.',
    );
  }
  final escaped = key.replaceAll("'", "''");
  db.execute("pragma key = '$escaped'");
  db.execute('select count(*) from sqlite_master'); // key does not self-validate
}
```

Ordering is mandatory: cipher configuration, then `PRAGMA key`, then everything else. WAL and other pragmas come after the key, never before.

`hooks: user_defines:` applies to the whole pub workspace, not one package — worth knowing before this repo ever becomes a workspace.
